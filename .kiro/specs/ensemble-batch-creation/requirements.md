# 需求文档：群像文批量创作

## 简介

群像文批量创作功能允许用户在一个共享的世界观和角色池中，选择多个创作工厂训练出的 Agent，让每个 Agent 以不同角色为主角视角，批量生成多条独立但相互关联的剧情线。同时引入爆款短剧方法论模块，在创作各阶段注入节奏、钩子、爽点等爆款元素，使生成的剧本更贴近真实的爆款短剧。

## 术语表

- **群像文项目 (EnsembleProject)**：包含共享世界观、角色池和多条剧情线的顶层项目容器
- **世界观 (WorldSetting)**：群像文项目中所有剧情线共享的时代背景、地点、社会环境和核心冲突设定
- **角色池 (CharacterPool)**：群像文项目中所有可用角色的集合，每个角色有完整的人设定义
- **剧情线 (StoryLine)**：以某个角色为主角视角展开的一条完整剧本，对应一个 ScreenplayProject 实例
- **交叉事件 (CrossoverEvent)**：在多条剧情线中同时出现的关键情节点，从不同主角视角呈现
- **写作Agent (WritingAgent)**：创作工厂通过进化算法训练出的写作风格代理，包含 systemPrompt、styleDirective、techniqueWeights 等属性
- **爆款方法论 (HitMethodology)**：从真实爆款短剧中提炼的创作规则集，包含节奏控制、钩子设计、爽点分布、付费卡点等策略
- **批量创作引擎 (BatchCreationEngine)**：负责并发调度多条剧情线生成的后端服务模块
- **剧本创作器 (ScreenplayCreator)**：现有的单剧本创作流水线服务

## 需求

### 需求 1：群像文项目管理

**用户故事：** 作为创作者，我希望创建和管理群像文项目，以便在一个统一的框架下组织多角色、多视角的剧本创作。

#### 验收标准

1. WHEN 用户提交群像文项目配置（题材、受众、基调、集数、世界观描述）时，THE 群像文项目管理器 SHALL 创建一个新的 EnsembleProject 并返回项目 ID
2. WHEN 群像文项目创建成功时，THE 群像文项目管理器 SHALL 将项目状态设置为 "init" 并持久化到数据库
3. WHEN 用户请求查看群像文项目列表时，THE 群像文项目管理器 SHALL 返回所有群像文项目及其当前状态和剧情线数量
4. WHEN 用户请求删除一个群像文项目时，THE 群像文项目管理器 SHALL 同时删除该项目下所有关联的剧情线和角色数据
5. IF 同时进行中的群像文项目数量达到上限（3个），THEN THE 群像文项目管理器 SHALL 拒绝创建并返回明确的错误提示

### 需求 2：世界观与角色池生成

**用户故事：** 作为创作者，我希望系统能基于我的设定自动生成共享世界观和角色池，以便多条剧情线在同一个故事宇宙中展开。

#### 验收标准

1. WHEN 用户触发世界观生成时，THE 世界观生成器 SHALL 基于项目配置生成包含时代背景、地点、社会环境、阶层关系和核心冲突的 WorldSetting 对象
2. WHEN 世界观生成完成后，THE 角色池生成器 SHALL 基于世界观自动生成不少于剧情线数量的角色，每个角色包含完整的人设（姓名、年龄、外貌、性格、公开身份、真实身份、动机、冲突点、人物弧光）
3. WHEN 角色池生成完成后，THE 角色池生成器 SHALL 同时生成角色之间的关系网络，包含至少一组对立关系和一组联盟关系
4. WHEN 用户手动编辑角色池中的某个角色属性时，THE 角色池管理器 SHALL 更新该角色数据并持久化
5. WHEN 用户向角色池中添加新角色时，THE 角色池管理器 SHALL 验证角色姓名在该项目内的唯一性
6. IF 世界观生成过程中 LLM 调用失败，THEN THE 世界观生成器 SHALL 返回错误信息并保持项目状态不变

### 需求 3：Agent 与角色绑定

**用户故事：** 作为创作者，我希望将创作工厂训练出的 Agent 分配给角色池中的角色，以便每个 Agent 以其独特的写作风格为该角色创作主角视角的剧情线。

#### 验收标准

1. WHEN 用户选择一个 Agent 并将其绑定到角色池中的一个角色时，THE 绑定管理器 SHALL 创建一条新的剧情线（StoryLine）记录，关联该 Agent ID 和角色 ID
2. WHEN 用户执行批量绑定（选择多个 Agent 并自动匹配角色）时，THE 绑定管理器 SHALL 根据 Agent 的 genre 和 tone 属性与角色的性格特征进行智能匹配
3. WHEN 一个 Agent 已绑定到某个角色时，THE 绑定管理器 SHALL 阻止同一项目内将同一 Agent 重复绑定到其他角色
4. WHEN 一个角色已被某个 Agent 绑定时，THE 绑定管理器 SHALL 阻止同一项目内将其他 Agent 绑定到该角色
5. WHEN 用户解除某条剧情线的 Agent-角色绑定时，THE 绑定管理器 SHALL 删除该剧情线记录，但保留角色池中的角色数据

### 需求 4：交叉事件设计

**用户故事：** 作为创作者，我希望定义多条剧情线之间的交叉事件，以便不同主角视角的故事在关键节点产生交汇，增强群像文的整体性。

#### 验收标准

1. WHEN 世界观和角色池就绪后，THE 交叉事件生成器 SHALL 基于世界观的核心冲突自动生成 3-5 个交叉事件，每个事件包含事件描述、涉及角色列表、发生时间点（集数范围）和事件类型（冲突/合作/揭秘/转折）
2. WHEN 用户手动添加交叉事件时，THE 交叉事件管理器 SHALL 验证涉及的角色均存在于角色池中
3. WHEN 批量生成剧情线时，THE 批量创作引擎 SHALL 将交叉事件注入到每条相关剧情线的对应集数中，确保同一事件在不同视角的剧本中保持事实一致性
4. WHEN 交叉事件涉及的角色在某条剧情线中不是主角时，THE 剧本生成器 SHALL 从该剧情线主角的视角描述该事件

### 需求 5：批量创作引擎

**用户故事：** 作为创作者，我希望一键启动多条剧情线的批量生成，以便高效地完成群像文的全部剧本创作。

#### 验收标准

1. WHEN 用户触发批量创作时，THE 批量创作引擎 SHALL 为每条已绑定 Agent 的剧情线创建独立的 ScreenplayProject，并注入对应 Agent 的写作风格配置
2. WHEN 批量创作进行中时，THE 批量创作引擎 SHALL 控制并发数量不超过配置的上限（默认 3 条剧情线同时生成）
3. WHEN 每条剧情线的创作阶段（创意方案/角色开发/分集目录/分集剧本）完成时，THE 批量创作引擎 SHALL 通过 WebSocket 向前端推送该剧情线的进度更新，包含剧情线 ID、当前阶段和完成百分比
4. WHEN 某条剧情线生成失败时，THE 批量创作引擎 SHALL 记录错误信息，继续执行其他剧情线，并在最终结果中标记失败的剧情线
5. WHEN 用户请求停止批量创作时，THE 批量创作引擎 SHALL 在当前正在生成的阶段完成后停止，保留已完成的内容
6. WHEN 所有剧情线生成完成时，THE 批量创作引擎 SHALL 汇总所有剧情线的状态（成功/失败/已停止）并通过 WebSocket 推送最终报告

### 需求 6：爆款短剧方法论注入

**用户故事：** 作为创作者，我希望系统在创作过程中自动注入爆款短剧的方法论，以便生成的剧本在节奏、钩子、爽点等方面更贴近真实的爆款短剧。

#### 验收标准

1. THE 爆款方法论模块 SHALL 提供一套可配置的爆款规则集，包含以下维度：黄金三秒开场规则、每集钩子类型分布（悬念钩/反转钩/情绪钩/信息钩/危机钩）、爽点节奏曲线（起势段/攀升段/风暴段/决战段）、付费卡点策略、对白密度控制
2. WHEN 生成创意方案时，THE 创意方案生成器 SHALL 将爆款方法论的节奏曲线和付费卡点策略注入到 LLM 的 system prompt 中
3. WHEN 生成分集目录时，THE 分集目录生成器 SHALL 确保每集的钩子类型标注符合爆款方法论的分布规则
4. WHEN 生成分集剧本时，THE 分集剧本生成器 SHALL 在 LLM prompt 中注入黄金三秒开场规则和对白密度控制要求
5. WHEN 用户选择不同的爆款强度等级（标准/强化/极致）时，THE 爆款方法论模块 SHALL 调整规则参数的严格程度

### 需求 7：群像文项目数据持久化

**用户故事：** 作为创作者，我希望群像文项目的所有数据能可靠地持久化，以便在服务重启后恢复项目状态。

#### 验收标准

1. WHEN 群像文项目的任何数据发生变更时，THE 持久化服务 SHALL 将变更写入 SQLite 数据库
2. WHEN 服务启动时，THE 持久化服务 SHALL 从数据库恢复所有群像文项目到内存中，包括世界观、角色池、剧情线绑定和交叉事件
3. WHEN 持久化写入失败时，THE 持久化服务 SHALL 记录错误日志并保持内存中的数据不丢失
4. FOR ALL 有效的 EnsembleProject 对象，将其序列化为 JSON 再反序列化 SHALL 产生等价的对象（往返一致性）

### 需求 8：前端群像文创作界面

**用户故事：** 作为创作者，我希望通过直观的界面管理群像文项目、配置 Agent-角色绑定、监控批量创作进度，以便高效地完成群像文创作。

#### 验收标准

1. WHEN 用户进入群像文创作页面时，THE 前端界面 SHALL 展示项目配置表单，包含题材选择、受众选择、基调输入、集数设置和世界观描述输入
2. WHEN 世界观和角色池生成完成后，THE 前端界面 SHALL 以卡片形式展示角色池中的所有角色，每张卡片显示角色姓名、公开身份和性格标签
3. WHEN 用户进入 Agent-角色绑定阶段时，THE 前端界面 SHALL 展示可用 Agent 列表和角色池，支持拖拽或选择方式完成绑定
4. WHEN 批量创作进行中时，THE 前端界面 SHALL 展示每条剧情线的实时进度条，包含当前阶段名称和完成百分比
5. WHEN 某条剧情线生成完成时，THE 前端界面 SHALL 提供该剧情线剧本的预览和导出入口
6. WHEN 批量创作全部完成时，THE 前端界面 SHALL 展示总览面板，汇总所有剧情线的状态和关键指标
