创作主流程（6大阶段）

0
参考小说解析（可选） analyzeReferenceNovel()

如果用户提供了参考小说，先用LLM提取故事DNA，作为后续所有阶段的二次创作基础。

📥 输入

用户粘贴的小说全文 / 上传的.txt文件

📤 输出

  • 故事线、核心冲突、主题
  • 角色关系图谱
  • 世界观设定
  • 剧情弧线（主要情节点）
1
创意方案生成 generateCreativePlan()

根据用户配置（题材、受众、集数、基调）生成完整的四幕结构创作方案。

📥 输入

  • 题材组合（如：都市+复仇）
  • 目标受众（男频/女频）
  • 总集数、故事基调、结局类型
  • 可选：参考小说解析结果
  • 可选：用户自定义要求

📤 输出 — CreativePlan

  • 3个剧名备选
  • 四幕结构（起承转合）+ 集数分配
  • 付费卡点布局（约12%集数）
  • 爽点矩阵（5类爽点占比）
  • 可选：跨时代时间线、伏笔/收线图谱、因果链

🏟️ 竞技模式

  • 10组 × 4人 = 40份方案
  • 组内互评修改 → 组间评审打分
  • 漏斗筛选 Top10 → Top1
  • 函数：runCreativePlanArena()

🔄 闭环迭代

  • loopCreativePlan()
  • 导师审逻辑 + 人性审爽感
  • 中枢裁决 → 修改 → 再审
  • 达标或达最大迭代次数后停止
2
角色体系设计 generateCharacters()

基于创意方案设计完整角色体系，包含主角、配角、反派的性格、动机、口头禅、视觉描述。

📥 输入

  • 阶段1的创意方案
  • 题材配置和受众信息

📤 输出 — CharacterDesign

  • 角色列表（名字、身份、性格、动机）
  • 角色关系网络
  • 口头禅、视觉描述
  • 秘密身份 / 隐藏动机

🎭 两条路径

  • 默认生成：LLM从零设计角色
  • 群演仓库匹配：从已有角色Agent库中匹配合适角色 + 补充新角色

🔄 闭环迭代

  • loopCharacterDesign()
  • 导师审角色合理性
  • 人性审角色代入感和冲突张力
2.5
世界观模拟（可选） worldSimulation

角色Agent在虚拟世界中自由互动，多轮模拟 + 跨组互动，提取关键事件注入后续写作上下文。

🎮 模拟流程

  • 多轮模拟：角色按组自由互动
  • 跨组互动：不同组角色碰撞
  • 汇总提取：关键事件和关系变化

💡 作用

  • 让角色行为在剧本中保持一致性
  • 发现意想不到的角色化学反应
  • 模拟日志注入剧本写作提示词
3
分集目录规划 generateDirectory()

规划每集的标题、梗概、钩子类型、所属阶段和付费卡点标记。

📤 输出 — EpisodeDirectoryItem[]

  • 每集：标题、梗概、钩子类型
  • 所属阶段（起势/攀升/风暴/决战）
  • 付费卡点标记 💰
  • 可选：时代归属、伏笔任务

📊 节奏分配

  • 起势段（前15%）：密集建立信息
  • 攀升段（15%-45%）：稳定上升
  • 风暴段（45%-80%）：高潮密集
  • 决战段（最后20%）：终极对决
4
逐集剧本撰写 generateEpisode() / generateEpisodeBatch()

按分集目录逐集生成完整剧本，包含场景描写（镜头指示）、台词对话、结尾钩子。

📥 注入上下文

  • 前一集结尾钩子
  • 角色简表（性格、口头禅）
  • 世界观模拟经历（如有）
  • 可选：Agent仓库的编剧风格

📤 输出 — EpisodeScript

  • 3-5个场景（镜头指示 + 台词）
  • 每场景4-6轮对话
  • 每集600-900字
  • 结尾钩子 + 下集预告

📏 质量硬标准

  • 1分钟 ≈ 250-300字
  • 台词占60-70%，描写占30-40%
  • 至少2种景别
  • 禁止无意义过渡场景

🔄 闭环迭代

  • loopEpisode() — 每集独立闭环
  • 导师审逻辑连贯性
  • 人性审爽点密度和钩子强度
5
质量评审 + 自动改写 reviewEpisode()

五维度质量评分，评审后自动改写，改写后复审确保分数不下降。

📊 五维评分（各1-10分，满分50）

  • 节奏：开场速度、紧张-舒缓交替
  • 爽点：数量、强度、类型多样性
  • 台词：废话比例、角色区分度
  • 格式：场景头、景别、音乐提示
  • 连贯性：前后集衔接、角色一致性

🔧 改写保护机制

  • 改写后复审，分数不低于原分才采纳
  • 字数缩水保护：台词和描写不能缩水超30%
  • 分数下降时自动重试一次
  • 重试仍失败则保留原剧本
6
导出 / 角斗场 exportScreenplay() / ArenaPanel

导出完整剧本文本，或进入角斗场进行剧本间的评分、对战、锦标赛和进化。

📦 导出

  • 完整剧本文本导出
  • 投稿材料生成（梗概、人物小传等）
  • 情绪锚点图（每分钟爽点分布）

🏟️ 角斗场

  • 剧本评分（六维雷达图）
  • 剧本对战（ELO积分制）
  • 锦标赛（淘汰赛/循环赛）
  • 吸收进化（败者吸收胜者优点）

🎓 导师Agent

专业逻辑官 · mentorReview()
  • 知识注入：根据题材提供行业黑话、法律常识、职场规则
  • 逻辑体检：审视因果关系，禁止"降智"剧情
  • 事实核查：检查医疗操作、商业合同、历史背景等常识
输出： logicTruth 评分 (0-100) + 反馈列表
颗粒度：具体到哪一场戏、哪一句台词
策略：不仅说哪里错，必须给出替代方案

💡 人性Agent

心理策略师 · humanityReview()
  • 钩子设计：前3秒必有冲突，前30秒必有反转
  • 情绪曲线：确保"憋屈（铺垫）"与"爽点（释放）"比例合理
  • 代入感：确保主角动机引发观众强烈共鸣
输出： emotionHook 评分 (0-100) + 反馈列表
心理框架：损失厌恶、社会比较、归属感渴求、复仇快感
爽点模型：压抑释放、身份反转、降维打击、打脸反馈

🧠 控制中枢（首席制片人）

nexusJudge() — 汇总意见、裁决冲突、生成修改清单
⚖️ 冲突裁决原则
  • 小逻辑服从大爽感
  • 但不能产生常识性硬伤
  • 逻辑硬伤导致出戏 → 优先修逻辑
  • 逻辑瑕疵不影响观感 → 保爽感
  • 最佳方案："合理的爽"
📋 输出内容
  • mergedFeedbacks — 合并去重的反馈
  • conflictResolutions — 冲突裁决说明
  • priorityActions — 优先修改项
  • passThreshold — 是否达标
  • scores — 三维评分（逻辑/爽感/对白）
✅ passThreshold = true
达标 → 输出成品
或
⚠️ passThreshold = false
未达标 → 生成修改清单
📝 buildRevisionPrompt() → 创作Agent修改
修改清单包含：当前三维评分 + 优先修改项 + 冲突裁决说明 + 详细反馈
修改原则：只改反馈指出的问题，保留优点，critical必须修复，不能缩水
revise() 回调 → 输出 V2.0 / V3.0 ... → 回到顶部继续审阅 🔄

验收阈值与评分体系

🎯 默认验收阈值

  • logicTruth（逻辑真实度）≥ 90
  • emotionHook（情绪爽感值）≥ 95
  • dialogueStyle（对白风格化）≥ 85

三项全部达标 → passThreshold = true → 停止迭代

📏 导师Agent评分标准

  • 90-100：逻辑严密，无硬伤
  • 70-89：有小瑕疵但不影响主线
  • 50-69：有明显逻辑漏洞
  • <50：逻辑混乱，需要重写

📏 人性Agent评分标准

  • 95-100：每一秒都在制造情绪，停不下来
  • 80-94：整体不错但有几处情绪断档
  • 60-79：爽点不够密集，可能划走
  • <60：平淡无奇，毫无吸引力

⚙️ 可配置项

  • 最大迭代次数（默认3轮）
  • 三项阈值均可自定义
  • 导师Agent额外知识注入
  • 人性Agent额外爆款基因注入
